EXTERNAL INTEGRATIONS
- Hunter.io Email Finder API (https://api.hunter.io/v2/email-finder) — REST GET,
  called with company={org} + first_name/last_name (split from a full name).
  Credential: API key in hunter_io_api_key.txt (gitignored). The same key is also
  embedded in the cloud routine's prompt, because cloud routines cannot read local
  files — if the key is rotated, update BOTH places.
  NETWORK REQUIREMENT: the cloud routine's sandbox blocks outbound HTTPS by default;
  api.hunter.io had to be added to the "Default" environment's egress allowlist
  (done manually 2026-09-09) before Hunter calls succeed. See CLAUDE.md.
- Supabase — project MAGTestProject, id aivitcomiywiysrfwqxt. Accessed by the
  routine via the Supabase MCP connector (execute_sql). Managed here via the
  Supabase MCP tools.

DATA STORES
- Supabase table public.linkedin_posts — the routine reads/writes these columns:
  status (text), is_verified_lead (bool), enrichment_poc_name (varchar, a full
  person name), org (text, company name), enrichment_email (text, the output),
  email_finder_is_processed (bool, the processed flag). No domain/website column,
  so Hunter is queried by company name.
  Current state: first successful run (2026-09-09) processed the backlog — of the
  qualifying set, 12 rows got an enrichment_email and 7 were marked processed with
  no match; 0 left unprocessed.
