EXTERNAL INTEGRATIONS
- Email finding is a TWO-PROVIDER CHAIN (since 2026-09-25): Clearbit domain lookup
  -> Hunter.io -> Prospeo fallback. Emails only (no phone/mobile).
- Clearbit Autocomplete (https://autocomplete.clearbit.com/v1/companies/suggest
  ?query={org}) — REST GET, free, NO API key. Resolves a company name to a domain;
  the routine stores the first result's domain in linkedin_posts.enrichment_company_
  domain (or 'unresolved' when none). Used to feed Prospeo an https:// company_website.
- Hunter.io Email Finder API (https://api.hunter.io/v2/email-finder) — REST GET,
  called with company={org} + first_name/last_name (split from a full name). Tried
  FIRST. Email at data.email. Credential: API key in hunter_io_api_key.txt.
- Prospeo enrich-person API (https://api.prospeo.io/enrich-person) — REST POST,
  header X-KEY, body {"data":{first_name,last_name,company_name,company_website,
  linkedin_url?}}. Tried as the FALLBACK on any Hunter miss. Email at
  response.person.email.email. GOTCHAS: company_website must be a full https:// URL
  (bare domain -> INVALID_DATAPOINTS); fields nest under "data"; free tier is
  rate-limited (429 -> ~2s spacing + one retry); free plan = 75 email credits/month
  (no rollover); classic Email Finder API is deprecated. Credential: API key in
  prospeo_api_key.txt AND GCP Secret Manager secret "prospeo-api-key" (project
  claudegwscli-502400, version 1). Gate-checked 2026-09-25: free-tier API access works.
- All three API keys are embedded in the cloud routine's prompt, because cloud
  routines cannot read local files — if a key is rotated, update the routine prompt
  too (and the Prospeo secret).
  NETWORK REQUIREMENT: the cloud routine's sandbox blocks outbound HTTPS by default;
  api.hunter.io (2026-09-09), then api.prospeo.io and autocomplete.clearbit.com
  (2026-09-25), had to be added to the "Default" environment's egress allowlist
  manually before calls succeed. See CLAUDE.md.
- Supabase — project MAGTestProject, id aivitcomiywiysrfwqxt. Accessed by the
  routine via the Supabase MCP connector (execute_sql). Managed here via the
  Supabase MCP tools.

DATA STORES
- Supabase table public.linkedin_posts — the routine reads/writes these columns:
  status (text), is_verified_lead (bool), enrichment_poc_name (varchar, a full
  person name), org (text, company name), enrichment_poc_linkedin_link (text, an
  optional Prospeo datapoint), enrichment_company_domain (text, NEW 2026-09-25 —
  Clearbit-resolved domain, or 'unresolved'), enrichment_email (text, the output),
  enrichment_email_source (text, now set to 'hunter' or 'prospeo'),
  email_finder_is_processed (bool, the processed flag).
  Current state (2026-09-25): 552 rows; 130 candidates (email null + poc_name + org),
  116 unprocessed at the time of the Prospeo build. The earlier Hunter-only run
  (2026-09-09) had filled 12 emails / marked 7 no-match.

PARENT PIPELINE (n8n) — this routine is one step in a larger workflow
- n8n workflow "Comment Scraping POC Enrichment" (id YAexztVMLu7zp3TN, active).
  Active path, from a daily 20:30 Schedule Trigger:
  1) Find POC: SQL pulls linkedin_posts needing a POC -> GPT-4.1-mini classifies
     "real speaking engagement?" -> if yes, Apify scrapes the post's comments ->
     JS matches a commenter whose position contains the first word of `org` ->
     writes enrichment_poc_name/title/linkedin_link (or "not found").
  2) Find email (Gemini pass): SQL pulls rows with a real POC not yet
     enrichment_is_processed -> Google Gemini (gemini-3-flash-preview) finds a
     verified/cited email -> writes enrichment_email + enrichment_email_source.
  3) Fire fallback: an n8n HTTP Request node (name "HTTP Request") fills the emails
     Gemini left blank. As of 2026-09-25 it POSTs to the Supabase Edge Function
     https://aivitcomiywiysrfwqxt.supabase.co/functions/v1/
     linkedin_comments_poc_enrichment (auth None). Previously it fired the Claude
     routine via POST .../claude_code/routines/trig_01KT.../fire (bearer auth).
  Separate daily 21:00 Schedule Trigger exports finished leads
  (enrichment_email set AND email_finder_is_processed=true AND not yet on sheet)
  to Google Sheet "ai_scraped_soc_med_leads"
  (docs.google.com/spreadsheets/d/1svksxHmNBUx9Z20t2kbtHAT1fThcfdCmz5dEp936L7I).
- Known gaps observed (not owned by this project): nothing sets
  enrichment_is_processed=true; and Gemini-found emails may never reach the sheet
  because the export requires email_finder_is_processed=true, which only this
  routine sets (and it skips rows that already have an email).
